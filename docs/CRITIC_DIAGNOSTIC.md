# Critic 第一阶段精简诊断

目的是检查已有 MATD3-Q 和最新 T-Q 的价值评价，不训练模型、不运行 MILP，也不生成正式测试、结算或训练曲线。

## 运行

在仓库根目录、原训练 Python 环境中，先核对模型来源：

```powershell
python scripts/diagnose_critic.py --check-only
```

这一命令会打印两个完整训练目录、最佳模型路径、最佳轮次、验证日期及计算规模。它不写诊断结果，也不进行候选动作回放。

正式运行精简诊断：

```powershell
python scripts/diagnose_critic.py
```

扩样诊断（24 个验证日，每月 2 天，两个预测噪声基础种子）：

```powershell
python scripts/diagnose_critic.py --days-per-season 6 --seeds 424242 525252
```

先加 `--check-only` 可检查日期、来源和规模，不写结果。扩样默认取每日每种子 6 个不同完整状态，共 288 个起点，最多 7488 条模型候选记录。`--days-per-season 3` 则每月取一天，共 12 天。

日期仅按日历和数据可用性选取：每月一个日期取中间位置，每月两个日期取该月可用日期序列约三分之一和三分之二处，不读取模型表现。所有模型共享同一日期、同一实际重置种子；实际种子为基础种子加日期索引。多种子的区间不得重叠。

默认用 CPU、单个 PyTorch 计算线程；小网络的逐步推理不一定在 GPU 更快。如需要可指定 `--device cuda`。

结果另存到新目录：

```text
outputs/diagnostics/critic_probe/<timestamp>/
```

不会更新任何训练目录的 `latest_run.json`，也不会写入原训练目录。已有输出目录禁止覆盖。

## 模型选择规则

仅检查这两个算法自己的工作结果目录：

- `matd3_dispatch_q_guided`：MATD3-Q。
- `matd3_hierarchical_transformer_q_readout`：最新设备预测读取版本 T-Q。

扫描每个目录的 `runs/`，选完成时间最新的**合格完整训练**；不直接相信 `latest_run.json`。

合格来源必须同时满足：

1. 算法名称与保存的配置一致，`run_purpose` 是 `formal_training`。
2. 至少训练 5000 轮；配置计划轮数、实际轮数、元数据、完整历史及总环境步数一致。
3. 训练已结束，正式评估已完成，测试日数量达到该次训练配置要求。
4. 最佳模型来自合格的验证选择，最佳轮次记录一致。
5. 只读取 `checkpoints/best_model.pt`；它的 SHA-256 必须与正式测试所用最佳模型记录一致。
6. 两次运行的环境配置快照完全一致；构建模型时使用各自保存的算法配置，而不是当前默认 YAML。

找不到合格来源会停止。不会退回短训练、冒烟结果、旧 T-Q 包或 `final_model.pt`。被排除的目录及原因记录在 `manifest.json`。

若要固定某次运行，可显式指定完整训练目录；相同验证规则仍然执行：

```powershell
python scripts/diagnose_critic.py --matd3-run "<MATD3-Q完整训练目录>" --tq-run "<T-Q完整训练目录>"
```

## 精简规模与比较方式

- 从验证集四个季度各取一天，不重新测试整个测试集。
- 同一日期两模型使用相同预测噪声种子；每个日期只用一个种子。
- 默认取 24 个共同状态：每日两个随机状态，加 EV 时间余量、HVAC 舒适边界、ESS 容量边界、负荷峰值压力各一个。
- 起点来自两个模型的轨迹；来源按日期交替，保证关键类别不固定只来自某个模型。找不到对应关键状态时明确标记回退。
- 对完整环境状态指纹去重；两个来源在初始时刻产生相同状态时，按原类别从同一来源选择下一个不同起点，保持来源平衡。扩样的每个起点 ID 包含实际种子。
- 对每个模型保留当前联合动作，并逐个将六个控制量改为 `-0.8/+0.8`，最多 13 个候选。
- 候选只替换当前一步，此后全部 Actor 使用自己的冻结参数，按变化后的观测继续调度到当天结束。
- 每个候选都重放相同历史动作重建起点；核对设备库存、EV 离站历史、历史峰值、交易历史、观测、预测数组及随机状态的完整指纹。
- 仅当投影控制相同、环境实际执行的第一步奖励和完整下一状态也相同，才复用候选的后续回报。
- 团队共享奖励只取一份。使用原 `gamma` 累加；原 `reward_scale` 用于成本单位换算。
- 每个控制量分别用对应微网 Critic 的 Q1、Q2 和 min(Q1,Q2) 评价原动作及两个候选。Q1 是 Actor 主损失使用的评价。

最多 624 次完整分支回放；真实等价动作会减少这个数量。控制台逐状态打印进度。

## 输出文件

| 文件 | 内容 |
|---|---|
| `manifest.json` | 来源、最佳模型校验值、排除原因、验证日期、噪声与候选设置、完成状态 |
| `state_pool.json` | 共同起点、来源、观测、历史动作与状态指纹 |
| `candidate_results.csv` | 每个候选的原始/投影动作、实际剩余回报、各微网 Q1/Q2、等价候选编号 |
| `state_scores.csv` | 每个状态与控制量的动作排序、选错成本、当前动作的候选改进空间 |
| `stratified_scores.csv` | 总体及分日期、季度、基础种子、起点来源、控制量的汇总 |
| `summary.json` | 汇总指标、实际回放量、耗时与来源完整性检查 |
| `report.md` | 按微网和 ESS/DR 汇总的中文阅读报告 |

CSV 采用 UTF-8 BOM，可以直接用 Excel 打开。计算中途出错会在清单中记录失败原因，并保留已完成状态的 CSV；失败目录不应当作完整结果。

## 解读边界

这是历史场景的实现回报，不是观测条件下精确的期望 Q，也不是 MILP 后续最优调度价值。TD3 目标策略平滑、预测误差与状态信息压缩都可能影响价值差异。

两个模型分别使用自身策略继续执行，因此参考价值也是各自的 Q。主要比较误判与选错代价，不能把不同模型 Q 的绝对数值直接作为优劣标准。

动作真实成本差不超过默认 1 个综合成本单位时，不计入有意义动作对的排序正确率。这个阈值可以用 `--tie-cost` 指定。gamma=1 时，剩余回报按原奖励尺度换算为剩余综合成本。

单个控制量候选只是一个有限诊断集，不代表全局最优动作。排序较好而当前动作较差时，还需检查局部梯度、饱和和投影，不能直接证明 Actor 容量不足。

汇总除平均值外，还提供中位数、P90、最大误选代价、前五例代价占比，以及相对原 Actor 动作改善/恶化超过成本容差的选择次数。先看跨日期与种子是否持续，再看平均值，避免少数异常值主导结论。不同候选分支不是独立日期样本，汇总代价也不是日均政策成本。

本阶段的数据使用实现未来回报，**不能直接作为满足部署信息条件的 Actor 教师标签**。
